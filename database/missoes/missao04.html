Missão 04

Identificação dos Recursos

Aprenda a identificar registros, conectar tabelas e manter a integridade dos relacionamentos usando chaves primárias e estrangeiras.

Nível: Intermediário

Objetivo: PK, FK e integridade

Checkpoint: 5 questões

Briefing

Cada recurso precisa de uma identidade

Em uma base operacional, dois clientes podem ter o mesmo nome e dois produtos podem ter descrições semelhantes. O banco precisa de identificadores confiáveis para distinguir registros e manter seus vínculos. É aqui que entram as chaves.

01 · Conteúdo

Primary Key e Foreign Key

Primary Key (PK)

Identifica cada registro de forma única. Não deve se repetir e não pode representar um valor desconhecido.

id_cliente INT PRIMARY KEY

Foreign Key (FK)

Armazena uma referência a uma chave de outra tabela. É o vínculo que transforma relacionamentos do modelo em estrutura lógica.

id_cliente INT → CLIENTE.id_cliente

Chave natural

Usa um dado do próprio negócio como identificador, como um código oficialmente único. Exige cuidado porque regras de negócio podem mudar.

Chave substituta

É criada apenas para identificação técnica, normalmente um número sequencial. Facilita relacionamentos e reduz dependência de dados do negócio.

02 · Demonstração

Do relacionamento para a chave estrangeira

CLIENTEPK id_clientenomeemail

1 ───── N

PEDIDOPK id_pedidodata_pedidoFK id_cliente

A FK id_cliente fica em PEDIDO porque PEDIDO está no lado N do relacionamento.

Regra operacional: a PK identifica. A FK conecta. Nunca confunda a função das duas.

03 · Integridade

O que a integridade referencial impede?

Sem integridade

Poderíamos cadastrar um pedido com id_cliente = 999 mesmo que esse cliente não existisse.

Com integridade

O SGBD verifica se o cliente referenciado existe antes de aceitar o pedido, evitando registros órfãos.
