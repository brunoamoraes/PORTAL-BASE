Missão 05

Construindo a Base

Transforme o modelo conceitual em estruturas lógicas com tabelas, campos, tipos, chaves e um dicionário de dados consistente.

Nível: Intermediário

Objetivo: Modelo lógico

Checkpoint: 5 questões

Briefing

O mapa agora precisa virar projeto técnico

No modelo conceitual pensamos no negócio. No modelo lógico definimos como as informações serão organizadas em tabelas, quais campos existirão, quais serão suas chaves e que tipo de dado cada coluna deverá receber.

01 · Conteúdo

Conceitual × lógico × físico

Modelo conceitual

Representa entidades, atributos, relacionamentos e regras do negócio sem se prender à implementação.

Modelo lógico

Organiza tabelas, campos, PKs, FKs e tipos de dados de forma compatível com o modelo relacional.

Modelo físico

Materializa o projeto em um SGBD específico, incluindo sintaxe SQL, tamanhos, constraints, índices e demais detalhes de implementação.

Dicionário de dados

Documenta cada campo: nome, significado, tipo, tamanho, obrigatoriedade, chave e observações.

02 · Tipos de dados

Escolha o tipo correto para cada informação

INT

Identificadores, contadores e valores inteiros.

VARCHAR(n)

Textos de tamanho variável, como nome, e-mail e descrição curta.

DECIMAL(p,s)

Valores que exigem precisão, como preços e totais monetários.

DATE / DATETIME

Datas e registros de data/hora para pedidos, reservas e auditoria.

Evite atalhos: preço não deve ser armazenado como texto e data não deve ser tratada como uma descrição qualquer. O tipo escolhido afeta validação, ordenação, cálculo e desempenho.
